UC4 · Waarderingsmodel

Who it's for

Valuation lead at Crowe. Analyst does the first pass; partner signs off on every parameter before a number leaves the model.

What problem it solves

Hours spent typing historicals into cells and arguing WACC in a spreadsheet — none of it advisory work. Partner time goes to defending numbers instead of choosing them.
UC5 · Teaser

Who it's for

M&A analyst drafting sell-side materials. Low judgment bar, high repetition. Partner only reviews the final polish — they don't touch the draft.

What problem it solves

Two hours per mandate spent retyping IM content into a template that never structurally changes. Mechanical work, done by the wrong person.
Speaker note · the first divergence This is where the "same pattern" cover starts to crack. Both have an analyst as primary user, but the partner's involvement profile is completely different — constant review for UC4, final polish for UC5. That alone predicts the build cost.

Probe Bram: "For the valuation model, is every parameter partner-reviewed, or only the high-stakes ones? Because that changes whether we need the adaptive-card conversation pattern I'll show in a minute."

UC4 · Stage 1 · Read three years, one pass

Extract the historicals before anyone argues

AI Builder + one generative AI node with a locked schema. Three annual reports go in, a typed JSON of five line items × three years comes out. This is the cheap part — and the part a Crowe analyst never has to retype again.

Generative AI node · system prompt Copilot Studio · Extract topic
Stage 1 · Read prompt You are an M&A analyst extracting three years of financials from a target's annual reports. INPUT: three PDF annual reports attached to the conversation (FY-3, FY-2, FY-1). Return ONLY valid JSON matching this schema — no prose, no markdown fences: { "prognose": { "revenue": [FY-3, FY-2, FY-1], "cogs": [FY-3, FY-2, FY-1], "personnel": [FY-3, FY-2, FY-1], "opex": [FY-3, FY-2, FY-1], "da": [FY-3, FY-2, FY-1], "tax_rate": <effective rate, last year, decimal> }, "notes": { "reclassifications": "one line describing any prior-year restatement, or null", "confidence": "high | medium | low" } } Rules - Normalise line items to template labels (personeelskosten → personnel, afschrijvingen → da). - If a line item is missing for any year, use null — never guess. - Reconcile prior-year restatements silently; note them in notes.reclassifications. - Amounts in EUR, integers, no thousand separators. - Output is consumed downstream as {{extracted}}.
Speaker note · why Stage 1 is the easy one This is the stage Bram has seen before — AI Builder territory. Point at the locked schema and say: "The discipline is that the output is typed. Stage 3 can't be robust if Stage 1 isn't."

Flag: Copilot Studio's generative node will occasionally wrap the JSON in markdown fences even when told not to. Either strip them in the next step or repeat the "no fences" rule — the prompt above already does.
UC4 · Stage 2 · Decide where the partner lives

The WACC conversation is the product

Eight adaptive cards, one partner, one loop. The agent proposes a value grounded in the IM or house-standards, cites the signal, and yields to a partner override without argument. This is the conversation-design work that makes UC4 a project, not a sprint.

Topic · system prompt Copilot Studio · WACC topic
Stage 2 · Decide prompt You help a partner confirm eight company-specific risk criteria for a WACC calculation. CONTEXT - {{extracted}} : the typed historicals from Stage 1. - {{im_text}} : the Information Memorandum, searchable. - {{house}} : house-standard defaults per firm-size bucket. For each of the eight criteria in order — illiquidity, customer_concentration, supplier_dependence, management_dep, activity_diversif, market_barriers, track_record, flexibility — run this loop: 1. Propose a value with ONE line of reasoning grounded in {{im_text}} or {{house}}. Example: "top-3 customers = 62% of revenue → customer_concentration 1.5%". 2. Render an adaptive card: slider (pre-filled), rationale field (pre-filled), source citation. 3. Wait for partner input. Accept any override silently — never argue, never re-propose. 4. Record the final value + the partner's one-line rationale to Dataverse. Never auto-fill `flexibility` — always ask with no default. After all eight are confirmed, ask: "Shall I write this to the valuation model?" Do not advance to Stage 3 until the partner answers yes. Output to Stage 3 as {{wacc_confirmed}}: an object of the eight keys with decimal values.
The eight criteria · grounded suggestions
  • Illiquidity — by firm-size bucket, default +1.0%
  • Customer concentration — from top-N revenue share in the IM
  • Supplier dependence — from sourcing footnotes
  • Management dependency — from the "key persons" paragraph
  • Activity diversification — from segment disclosures
  • Market barriers — qualitative with a confidence flag
  • Track record — from the revenue/EBITDA trend
  • Flexibility — always partner input, never auto-filled
Copilot Studio building blocks
  • Topic + adaptive card — one card per criterion, slider + rationale
  • Variables & entities — carry {{extracted}} across turns without re-asking
  • Generative answers — grounded on a SharePoint library of past valuation memos
  • Dataverse table — shared state between stages
  • Child Power Automate flow — fires Stage 3 only after the partner says yes
Speaker note · this is where the valuation agent is actually hard Emphasise: "This is not a prompt-engineering problem. It's a conversation-design problem." The agent has to know how to suggest, how to cite, and how to gracefully yield.

Ask Bram: "For the eight criteria — how much is house view versus per-partner preference? If every partner runs it differently, the agent needs a partner-selectable profile; if there's a house standard, it's easier."

If someone asks "why not let it set WACC on its own?": because the output is defensible only if the partner can point at each number and say why. The agent's job is to make that defence faster, not replace it.
UC4 · Stage 3 · Write named ranges, not coordinates

The JSON contract is the handshake

One merge step, one Office Scripts call. A generative node stitches Stage 1 output + Stage 2 decisions + house-standards into the payload the script expects. Because the script reads named ranges, the model template can version-bump without breaking anything upstream.

Generative AI node · merge prompt
Assemble the payload Copilot Studio
Stage 3 · Write prompt Assemble the Office Scripts payload for the valuation model. INPUT - {{extracted}} : historicals from Stage 1 - {{wacc_confirmed}} : partner-confirmed criteria from Stage 2 - {{house_standards}} : risk_free, market_prem, size_prem from Dataverse (by firm-size bucket) OUTPUT: valid JSON, exactly this shape — no prose, no fences: { "prognose": { ...from {{extracted}}.prognose }, "wacc": { "risk_free": <decimal from house_standards>, "market_prem": <decimal from house_standards>, "size_prem": <decimal from house_standards by firm-size bucket>, "company_risk": { ...eight keys from {{wacc_confirmed}} } } } Rules - Every numeric value is a decimal (0.0272, not "2.72%"). - If any of the eight criteria in {{wacc_confirmed}} is missing, halt and raise an error — never default silently. - Pass the result into the child Power Automate flow verbatim.

Speaker note · the unlock you want Bram to take home Say this line: "Once you've agreed on a JSON contract against named ranges, filling any Excel model is a solved problem." Pause on it — this is the takeaway.

The reference payload on the right is copy-able for a reason — a Crowe engineer can paste it into a sticky note, build the matching Office Script this week, and the agent is then purely a UI problem.

Known Copilot Studio limitation: agents can't natively read a complex Excel back for verification. Writes via Office Scripts are fine; audit-after-write is clunky. Build a human confirmation step into the adaptive card before firing Stage 3.

UC5 · the token-replace pattern how the PPTX gets filled

Placeholder tokens the flow swaps in

The template carries tokens directly in its text frames. The flow unzips the .pptx, finds and replaces on the slide XML, rezips, saves. 30–50 lines of code, no custom connector, no Azure Function.

Examples & tips fill · patterns to reuse

Patterns to capture on each canvas

UC4 · pattern A

Adaptive-card parameter loop

One card per judgment criterion: grounded suggestion + slider + confirm. Reusable for any valuation parameter a partner would never let an agent set alone.

UC4 · pattern B

Named-range payload write

One Office Scripts call per sheet, accepting a typed JSON payload. Immune to cell-coordinate drift when the model template version-bumps.

UC5 · pattern A

Token-in-template PPTX fill

Author the template with {{token}} placeholders. Agent produces typed JSON; flow does find/replace on slide XML. Robust and boring.

UC5 · pattern B

Typed-JSON generative node

Force the Generative AI node to return a strict JSON shape — not prose. Makes downstream replace/parse deterministic. Reuse the shape for any templated sell-side deliverable.

Speaker note · this is the takeaway layer The patterns listed here are what we put on each canvas. They're reusable — the adaptive-card parameter loop will reappear the moment anything else needs partner judgment in the flow, and the typed-JSON generative node is the pattern for any templated output.

Ask Bram: "Which of these four patterns would you actually open next Monday?" The answer tells you where the team's centre of gravity sits — and which pilot to lead with.
