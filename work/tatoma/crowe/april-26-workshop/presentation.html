Section 1 · 10 minutes

Why Claude?

Our tool of choice for knowledge work. Why it matters for M&A, and why we chose it for the first two demos.

About Claude

It reads the way a consultant reads

Built by Anthropic. Not keyword scanning — contextual reasoning over long, complex documents. Give it a 33-page IM and it comes back with analysis you can take seriously.

Long documents
200K

tokens of context — roughly a 400-page IM in one pass. No chunking, no "did it actually see page 27?" — the whole document stays in working memory.

Critical reading
Catches gaps

Holds long documents in memory and notices what a tired analyst might miss on page 27 — weak normalization justifications, terms defined inconsistently across files.

Dutch language
NL

Reads and writes Dutch fluently. Annual reports, templates, jaarrekening terminology — no translation step. (For dense legal reasoning we still sometimes prompt in English and have it answer in Dutch.)

Structured output
→ Table

Ask for a risk register, comparison matrix, or filled Excel template and you get it in that shape — not prose you then have to reformat. Review the contents, not the formatting.

Speaker note Keep it grounded. "You know ChatGPT, Copilot. Good tools. But for work where accuracy and nuance matter, Claude is in a different league. The difference isn't speed — it's quality of analysis."

Spine 1 — what works

Four patterns, six use cases

Every use case today is one of four patterns. Learn the patterns, and the use cases stop being six separate problems — they become four variations of work you already understand.

Pattern 1 · Analyze
doc → insight

Document Analysis

One document in. Structured reasoning out. Risks, questions, assessments.

→ UC1 · IM Review
Pattern 2 · Compare
doc + doc → diff

Cross-Doc Comparison

Two versions of a deal document. Discrepancies, who benefits, what's material.

→ UC2 · NBO ↔ Term Sheet
Pattern 3 · Fill
source + template → output

Template Filling

Source document + empty template. Right data, right cells, flagged gaps.

→ UC3 · UC4 · UC5
Pattern 4 · Extract
mess → structure

Data Extraction

Messy, unstructured input. Clean, analyzable structured data at the other end.

→ UC6 · Audit files

What you'll judge

Not "was it fast" — speed is obvious. The question is whether the analysis would hold up in an internal buyer memo.
