Section 01

Problem Statement

The current Tool Catalog is a flat grid of cards showing tool name, vendor, one category tag, and an AI maturity label (Low/Medium/High). It has three critical failures:

Failure 1 — No discovery

Tools are dumped in a grid with only category chip filters. There's no search, no CIB domain navigation, no "recommended for you," no way to explore by work context. Employees scroll through 55+ identical-looking cards with no guidance.

Failure 2 — Empty cards

Each card shows a letter avatar (no real logos), the tool name, the vendor name, a single category badge, and an AI maturity colour label. There's no description of what the tool does with AI, no learning content hooks, no org adoption context beyond a small "Used by your org" tag on some cards, and no progress indicators.

Failure 3 — No connection to learning

The catalog exists in isolation. There's no link from a tool to Academy courses, no proficiency tracking, no reason for an employee to come back. It's a reference list, not a learning surface.

The goal

The catalog needs to become a place where employees discover what AI can do in the tools they already use, and have a clear path to learn more.

Section 02

Design Principles

These five principles should guide every design decision:

Adoption over discovery

Employees don't need 4,000 tools — they need the 15–30 tools their org uses and what AI can do inside them. Default to "My Org's Stack."

Work context first

Navigate by CIB domain (how employees think), not by tool type (how developers categorise). "Help with customer contracts?" before "show me CRM tools."

Bidirectional learning

Every tool page surfaces related courses. Every course surfaces related tools. The catalog and Academy are two views of the same learning journey.

Show, don't require clicks

Card-level information density matters. Scanning the grid should teach something useful without clicking into a detail page.

Professional, not gamified

Progress tracking uses "proficiency levels" and clean progress bars — not XP, confetti, or cartoon badges. Frame everything as career development.

Section 04

Information Architecture

4.1 Page structure

Academy Learn page ├── Courses (existing) └── Tools Catalog (new — tabbed or sectioned) ├── Hero / intro area │ ├── Title + subtitle │ ├── Search bar (prominent) │ └── "My Org's Stack" / "Explore All Tools" toggle ├── CIB Domain navigation (6 domain tiles) ├── Filter panel (left sidebar desktop, slide-out mobile) ├── Results area │ ├── Active filter pills + result count │ ├── Sort dropdown + Grid/List view toggle │ └── Tool cards └── Tool Detail Page (navigated to from card click)

4.2 CIB domain navigation

The six CIB domains are the primary navigation axis. They appear as visual tiles with icons and tool counts above the grid, replacing the current flat category chips.

Why this change

Employees asking "How can AI help me with my customer work?" think in domain terms. The current category-first taxonomy (Analytics & BI, Collaboration, Communication…) is a developer's view of the world, not an employee's.

4.3 "My Org's Stack" vs. "Explore All Tools"

A prominent toggle at the top switches between two views. "My Org's Stack" is the default — showing only tools linked to the org via landscape_tools. "Explore All Tools" shows the full catalog (55+ tools) where org-adopted tools get a "Used by your org" badge and non-adopted tools show "Request access."

Why default to org stack

The competitive research and Mathijs feedback both confirm that employees want to work with tools they already have. Showing 55+ tools by default creates the same choice paralysis that consumer directories suffer from.

The AI capability description is the single most important addition. It answers "what can AI do in this tool?" — not what the tool itself does. Employees already know what Slack is; they need to know what Slack's AI features do.

The exploration counter ("3 of 5 explored") is driven by users marking resources as "I have tried this" on the detail page. When nothing has been explored, this area shows an "Explore resources →" CTA instead. This is a lightweight v1 proxy for learning progress — the full proficiency model (Aware → Expert) with Academy courses is deferred to v2+.

5.2 List card (dense comparison view)

For evaluation workflows, a denser row format accessible via a Grid/List toggle. It surfaces all comparison-relevant data (domain, maturity, level, org status, courses) without requiring click-through.

5.3 "Common in your industry" badge

Instead of a generic badge, show specific data: "Used by 73% of Professional Services orgs" — based on aggregated landscape_tools data across orgs in the same context_org_profiles.industry.

Section 07

Search & Filtering

7.1 Search

Full-text search across tool names, vendor names, AI capability descriptions, use-case examples, and tags. The search bar must be prominent at the top of the catalog — not hidden behind filters. Typeahead results should be grouped by CIB domain. Search must be reliable — Futurepedia and Insidr.ai both fail here.

7.2 Filter panel

Left-panel on desktop, slide-out on mobile. Real-time result counts on each filter option.

Section 08

Resources, Use Cases & Progress (v1)

V1 reality check

TATOMA doesn't yet have its own Academy learning content per tool. In v1, the catalog provides curated external resources and connects tools to Academy discovery use cases. Full bidirectional learning integration with Academy courses, proficiency levels, and certification is deferred to v2+.

8.1 Curated resources — three management layers

Layer 1

Global defaults

TATOMA-curated: 3–5 resources per tool (vendor docs, YouTube tutorials, blog posts). Stored on landscape_tools_catalog. Baseline for all orgs.

TATOMA-managed
Layer 2

Org overrides

Admins add, remove, or reorder resources for their org via Admin/Workbench. Example: adding an internal "How we use Power BI" guide.

Admin-managed
Layer 3

User suggestions

Employees submit useful links via "Suggest a resource." Enters moderation queue in Admin/Workbench. Approved = becomes org resource.

Moderated

Each resource on a detail page shows: title, source name (e.g., "Microsoft Learn"), type icon (📄 article, 🎥 video, 📘 docs), and an "I have tried this" button.

8.2 "I have tried this" tracking

How it works

Each resource has a toggle. When marked, it increments the user's exploration count for that tool. This drives the "3 of 5 explored" counter on tool cards. It's a lightweight, honest proxy for learning progress — the user self-reports having engaged, not that they've mastered anything. Sets the foundation for the full proficiency model in v2+.

Card stateDisplay
No resources explored"Explore resources →" CTA
Partially explored"2 of 5 explored"
All explored"✓ All resources explored"

8.3 Tool ↔ Use case connection

Tools connect to personal use cases from the Academy discovery feature. This is the bridge between "what tools exist" (catalog) and "what can I do with AI" (discovery). The tool detail page shows linked use cases; employees can mark "I've done this" to build their personal use case portfolio in the Academy. The connection is bidirectional — the discovery feature can also surface which tools support a given use case.

8.4 Comments on tools

Employees can leave org-scoped comments on tool pages — tips, experiences, questions. Chronological order, no voting in v1. This is a lightweight community layer; formal peer use-case examples with structured templates and helpfulness voting are deferred to v2+.

8.5 What's deferred to v2+

Full learning integration (requires Academy content per tool)

Bidirectional Academy course integration · Proficiency model (Aware → Familiar → Proficient → Expert) · Academy-authored courses, assessments, certifications per tool · Learning path sequencing · Team proficiency dashboards · Industry benchmarking on proficiency

Section 09

Request-a-Tool Flow

Three tiers based on tool status, with friction calibrated to risk:

Tier 1

Self-serve

Tool already licensed by org. Employee clicks "Start learning" and immediately accesses Academy content.

Zero friction
Tier 2

Lightweight request

Tool in catalog but not adopted by org. Pre-populated form (name, team, CIB domain auto-filled, use case). 2-click submission. Creates landscape_tool_review_requests entry.

Low friction
Tier 3

Suggest a new tool

Tool not in catalog at all. Form: tool name, vendor, URL, CIB domain, justification. Admin can add to catalog if appropriate.

Full form
Section 10

Personalisation Layers

For the initial build, implement two of the four personalisation layers:

Layer 1 — Organisation (v1)

"My Org's Stack" default view showing tools from landscape_tools. Industry context for "Common in your industry" badges from context_org_profiles.industry. Org-level resource overrides managed in Admin/Workbench.

Layer 2 — Individual (v1, lightweight)

"I have tried this" resource exploration tracking. Bookmark/favourites for personal collections. Comments on tool pages. "Continue where you left off" on the catalog homepage.

Deferred to v2

Full proficiency tracking (Aware → Expert, requires Academy content). Team/Department layer: Team-specific recommendations, team proficiency dashboards. Role layer: Role-based CIB domain weighting, recommended learning paths. Onboarding flow: 3-step personalisation wizard.

Section 12

Acceptance Criteria

Must have (v1)

  • Tool cards show: real logo, name, vendor, AI capability description (120 chars), CIB domain badge, AI maturity level, org badge, resource count, exploration counter ("X of Y explored") or "Explore resources →" CTA, up to 3 tags
  • CIB domain tiles as primary navigation (6 domains with tool counts)
  • "My Org's Stack" / "Explore All Tools" toggle, defaulting to org stack
  • Search bar with full-text search across tool names, vendors, descriptions, tags
  • Filter panel: CIB domain, tool type, org status, AI maturity, learning progress
  • Sort options: recommended, most adopted, most resources, AI maturity, recently added, alphabetical
  • Grid view (default) and List view toggle
  • Tool detail page with: hero, AI capabilities, curated resources, use cases, comments, evaluate/compare
  • "Used by your org" badge on cards for tools in the org's landscape_tools
  • "Common in your industry" badge with percentage based on cross-org aggregation
  • Curated resources per tool: TATOMA global defaults (3–5 per tool), org-level overrides in Admin/Workbench
  • "I have tried this" toggle on resources, driving card-level "X of Y explored" counter
  • User-suggested resources with moderation queue in Admin/Workbench
  • Use cases from Academy discovery feature linked to tools on detail pages
  • Org-scoped comments on tool detail pages
  • Request-a-tool flow (Tier 2 and Tier 3) creating landscape_tool_review_requests entries
  • Accessible to all Academy users (read-only catalog, write for requests and bookmarks)

Should have (v1 stretch)

  • Bookmark/favourites system for personal tool collections
  • "Ideal for" use cases on detail pages
  • Balanced Pros/Cons on detail pages
  • Clickable hashtag tags that filter the catalog

Deferred (v2+)

  • Bidirectional Academy course integration (tool pages ↔ Academy courses)
  • Proficiency model (Aware → Familiar → Proficient → Expert) replacing exploration counter
  • Academy-authored learning content per tool: courses, assessments, certifications
  • Side-by-side tool comparison (2–3 tools in same CIB domain)
  • Structured peer use-case examples with templates + helpfulness voting
  • Team proficiency dashboards
  • Industry benchmarking dashboards for org admins
  • Role-based personalisation + onboarding wizard
  • "Recommended for you" feed + "Trending in your org"

Appendix: what "AI maturity" means

Low

Announced or beta-testing AI features, limited in scope or not yet production-ready.

Medium

Shipped production AI features covering some workflows, but significant manual work remains.

High

Deeply integrated AI across core workflows, meaningfully reducing manual effort for most users.
