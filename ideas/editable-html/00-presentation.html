Section 1 · 10 minutes

Why Claude?

Our tool of choice for knowledge work. Why it matters for M&A.

About Claude

It reads the way a consultant reads

Built by Anthropic. Not keyword scanning — contextual reasoning over long, complex documents. Give it a 33-page IM and it comes back with analysis you can take seriously.

Long documents
1M

tokens of context — roughly 2,000 pages, a full deal room in one pass. No chunking, no "did it actually see page 27?" — every term, footnote, and annex stays in working memory while it reasons.

Methodology, not prompt
Follows a rubric

Hand it your review checklist, playbook, or template. It applies the same rigor to file 1 and file 29 — consistent, not paraphrased, not shortcut on the last one.

Honest about uncertainty
Flags gaps

Says "the IM doesn't disclose customer concentration" instead of filling it in with a confident guess. Weak normalization justifications, inconsistently defined terms — surfaced, not hidden.

Dutch language
NL

Reads and writes Dutch fluently. Annual reports, jaarrekening terminology, templates — no translation step. (For dense legal reasoning we still sometimes prompt in English and have it answer in Dutch.)

Speaker note Keep it grounded. "You know ChatGPT, Copilot. Good tools. But for work where accuracy and nuance matter, Claude is in a different league. The difference isn't speed — it's quality of analysis." If asked about the 1M number: that's Sonnet 4.5/4.6 today; Opus and Haiku sit at 200K. For M&A it's the Sonnet class we use.
Where you work with Claude

Three surfaces, one tool

At Tatoma, Claude is how we work every day. Contract analysis, financial documentation, proposals, report reviews. What took a day takes an hour — with better structure.

Three interfaces, each tuned for a different kind of work. Same model underneath, different ergonomics.

Claude Chat

Quick analysis & reasoning

Upload a document, get insight. The conversational surface — where UC1 and UC2 live this afternoon.

Claude Cowork

File-heavy work

Desktop tool with folder access and a sandboxed shell. Reads docs, fills templates, creates deliverables. A capable junior with perfect attention to detail.

Claude Code

Technical workflows

Terminal-native agent for developers. Data pipelines, parsing large files, building systems — the engineering layer.

Speaker note Honest about limits — AI output is a strong first draft, never a final answer. Today's demos use Chat (UC1, UC2). Cowork is what we'd use for UC3–5 in our world; Code is how we'd tackle UC6. You'll see the parallels when we get to Copilot Studio — Microsoft's stack has its own version of these three layers.
What makes it a colleague, not a chat box

The agentic layer

Claude doesn't just answer — it works. Reads files, writes and runs code, fills templates, browses, searches. And when wired up, it plugs into your stack. Three layers make that possible.

Native tool use

What Claude does on its own

Write & run code. Read, edit, create files. Browse the web. Produce structured output — Excel, Word, slide decks. You don't pick the tool — you state the goal, Claude picks the tool and reports back with the work done.

Skills

Your methodology, encoded

A skill is a reusable capability bundle — your review rubric, your template library, your house style — packaged once so every analyst runs the same rigor. These slides were built by the pptx skill, step by step.

MCPs & connections

Plugged into your stack

MCP (Model Context Protocol) is the standardized connector layer. DMS, CRM, mail, databases, Notion, Slack, SharePoint. Claude reads and acts across them. This is where AI-as-assistant becomes AI-as-colleague.

Put differently: tool use is what Claude can do, skills are how you teach it your way, and MCPs are what you connect it to. Stack the three and you get a working agent, not a smarter search box.

Speaker note Point of this slide: Claude isn't a chat box. "Agentic workflow" = tool use + skills + MCPs, stacked. UC3 onwards we switch to Copilot Studio — that's Microsoft's equivalent stack inside their environment: actions (tool use), topics & knowledge (skills), connectors (MCPs). Same thinking, different letters. If anyone asks what MCP is: an open protocol Anthropic published — Microsoft, Google, and others have since adopted it. Your DMS vendor probably has one or will soon.

Spine 1 — what works

Four patterns, six use cases

Every use case today is one of four patterns. Learn the patterns, and the use cases stop being six separate problems — they become four variations of work you already understand.

Pattern 1 · Analyze
doc → insight

Document Analysis

One document in. Structured reasoning out. Risks, questions, assessments.

→ UC1 · IM Review
Pattern 2 · Compare
doc + doc → diff

Cross-Doc Comparison

Two versions of a deal document. Discrepancies, who benefits, what's material.

→ UC2 · NBO ↔ Term Sheet
Pattern 3 · Fill
source + template → output

Template Filling

Source document + empty template. Right data, right cells, flagged gaps.

→ UC3 · UC4 · UC5
Pattern 4 · Extract
mess → structure

Data Extraction

Messy, unstructured input. Clean, analyzable structured data at the other end.

→ UC6 · Audit files
