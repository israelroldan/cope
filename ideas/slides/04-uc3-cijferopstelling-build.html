Architecture · five nodes end-to-end what we're building

Five nodes. One per job.

Why this stack. A Copilot Studio agent gives us the chat UX. A Power Automate flow is the tool it calls. AI Builder's "Create text with GPT" is the fastest way to a reliable JSON extraction without custom code. Excel Online closes the loop with a real file.

Two alternatives we rejected. A flow without an agent — works but unimpressive as a live demo. A declarative agent with document upload — fast to build, but it can't write into a template at precise cells. Our pick is the only path that's end-to-end.

Speaker note · draw this on the whiteboard too Walk the arrows, one at a time, ten seconds each. Name each node with a verb: trigger, extract, reason, map, output. That vocabulary shows up again in the build steps.

If they push on "why not just the AI Builder prompt alone?" — answer: because we need a file on disk at the end, not a chat answer. The mapping node is what turns this from a demo into a deliverable.

~3 min
02

04
Use the structured outputBecause we set JSON in step 3, the prompt's fields are exposed as dynamic values downstream — no separate Parse JSON action needed. If we stayed on plain-text output, add Data Operation → Parse JSON here instead.

Expected output  ·  the extraction prompt the core

The one prompt that does the thinking

Our hypothesis: a single GPT-4.1 prompt (or Claude Sonnet 4 via the multi-model lineup), with the full PDF text and the target year, returns a structured JSON of the 30-odd fields — with null for missing, a confidence tag, and ambiguity notes.
AI Builder · Create text with GPT paste into the prompt designer
KleurRijker BV 2024.pdf Template cijferopstellingIM.xlsx
AI Builder · Custom GPT prompt You are a financial analyst assistant extracting data from a Dutch annual report (jaarrekening, Dutch RJ / Richtlijnen Jaarverslaggeving format). INPUT - Full text of the annual report: {{annualReportText}} - Target reporting year: {{targetYear}} TASK Extract the financial figures for {{targetYear}} that match the line items below. All figures are in EUR. If the report shows amounts in thousands, convert to full euros. If a line item is not present in the report, return null — do NOT guess. OUTPUT Return ONLY valid JSON, no prose, using this exact schema: { "year": <number>, "sourceDocument": "<filename or title found in the document>", "currency": "EUR", "unitsInReport": "units" | "thousands", "profitAndLoss": { "nettoOmzet": <number|null>, // Net revenue "kostprijsVanDeOmzet": <number|null>, // Cost of goods sold "brutowinst": <number|null>, // Gross profit "personeelskosten": <number|null>, // Personnel costs (lasten uit hoofde van personeelsbeloningen) "lonenEnSalarissen": <number|null>, "socialeLasten": <number|null>, "pensioenlasten": <number|null>, "afschrijvingen": <number|null>, // Depreciation and amortisation "huisvestingskosten": <number|null>, "verkoopkosten": <number|null>, "autokosten": <number|null>, "kantoorkosten": <number|null>, "algemeneKosten": <number|null>, "overigeBedrijfskosten": <number|null>, "ebitda": <number|null>, "ebit": <number|null>, "financieleBatenEnLasten": <number|null>, "resultaatVoorBelastingen": <number|null>, "belastingen": <number|null>, "resultaatNaBelastingen": <number|null> }, "balanceSheet": { "materieleVasteActiva": <number|null>, "immaterieleVasteActiva": <number|null>, "financieleVasteActiva": <number|null>, "voorraden": <number|null>, "vorderingen": <number|null>, "liquideMiddelen": <number|null>, "totaalActiva": <number|null>, "eigenVermogen": <number|null>, "voorzieningen": <number|null>, "langlopendeSchulden": <number|null>, "kortlopendeSchulden": <number|null>, "totaalPassiva": <number|null> }, "notes": [ "<short free-text note for anything ambiguous or worth flagging>" ], "confidence": "high" | "medium" | "low" } RULES 1. Dutch reports often show two years side-by-side. Extract only the {{targetYear}} column. 2. Preserve sign conventions from the report (costs as positive numbers when shown that way). 3. If a value is aggregated in the report (e.g., "Overige kosten" combines several template line items), put the total in the closest matching field and add a short entry to "notes". 4. If the audit report, directors' report, or disclaimer section contradicts the figures, trust the financial statements section. 5. Set confidence = "low" if more than 3 fields are null or if the report structure deviates significantly from Dutch RJ format.
Speaker note · the prompt is the product The prompt — not the flow — is the reusable artifact here. Everything else is plumbing. Point at the three design choices the room should notice: (1) return null, don't guess, (2) notes array for ambiguity, (3) confidence tag for downstream review.

If the room's finance people want to argue about which line items belong — great, that's the right conversation. The prompt is meant to be edited. Suggest: "we'll version this in a SharePoint list so your team owns it, not us."
Test phase · run, compare, discuss 12 min

Does it actually work on your PDF?

Run (≈4 min). Open the published agent in Teams. Upload KleurRijker BV 2024.pdf. Ask: "extract the financials for 2023." Narrate the flow steps as they execute. Wait 30–60 seconds. Click the returned share link — the template opens with values populated.

Compare to UC1 (≈3 min). Pull up the IM review output from this morning side-by-side. Did both agree on netto-omzet and brutowinst? Where did they diverge? Which one flagged ambiguity better?

Discuss (≈5 min).

  • What would you accept without human review?
  • Where are the gaps (forecast, klanten/leveranciers) and what's the right follow-up pattern for each?
  • How do we surface the confidence and notes fields in a review workflow?
  • Scale: 3 years × 30 rows — one GPT call per PDF or fan-out?
Speaker note · let the stream be the show Hit send, then stop talking. The flow has to run — don't narrate over the wait. If it takes more than 90 seconds, start the compare-to-UC1 conversation while it finishes; don't stare at the spinner.

Expected divergences between UC1 and UC3: Claude tends to narrate uncertainty in prose; this pipeline puts it in the notes array and confidence field. Call out that this is a deliberate design choice — it's what makes the output reviewable at scale.
